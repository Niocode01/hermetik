## F4 — provisioner + gateway + transporte atestiguado
Diseño: `docs/adr/ADR-01-transporte-y-atestacion.md`
- [x] Contrato de provisioning: orden de `access` → provisioner → contenedor
- [x] `provisioner/` mock con URL de inquilino, marca `dev-unattested:` obligatoria y modo
      `real` que FALLA en vez de degradar. 40/40 tests.
- [x] Verificador de atestación en el cliente (capa 2) con **13 casos negativos** que prueban
      que RECHAZA: firma corrupta, `report_data` de otra sesión, caducado, raíz desconocida,
      vendor inesperado, binario distinto. 19/19 tests.
- [x] Handshake de sesión ligado a la atestación (capa 3): `report_data` entra en el IKM de
      HKDF, así que un enclave no genuino deriva otra clave y el canal falla. **Bucle cerrado**:
      `session.ts` ahora hace el POST `/v1/session` con su `client_pub` y exige `session_id`
      (fail-closed); el servidor (`attest_server.py`) deriva el MISMO secreto compartido.
      15/15 tests de sesión (incluye "envía client_pub de 32 B" y "aborta sin session_id").
- [x] Gateway acepta nb2 (valida on-canister vía `access.verify_credential`):
      `gateway/nb2.py` (port fiel del wire format CBOR+candid de
      `platforms/nebulock.py`). El gateway NO conoce el secreto HMAC — lo valida
      el canister por query anónima. Fail-closed: estructura + `who ==
      X-Nebulock-User` (defensa en profundidad) + on-canister. 20/20 tests.
- [x] Endpoint `/v1/attest` + `/v1/session` en el gateway (mock y real):
      `gateway/attest_server.py` (handshake servidor, espejo de `session.ts`) +
      `gateway/app.py` (aiohttp: `/health`, `/v1/attest`, `/v1/session`,
      `/v1/whoami` protegida por nb2). **Interop probada byte a byte**: el
      servidor Python deriva la MISMA clave que un cliente WebCrypto real
      (Node vía `attest_interop.mjs`, espejo de session.ts). Modo real FALLA en
      vez de degradar; `DEV_ATTEST=1` explícita para emitir dev. 15+6 tests,
      incluidos HTTP en vivo sobre puerto efímero.
- [x] Canal cifrado (ADR-01 paso 5): `gateway/channel.py` — AES-256-GCM con
      contador por dirección (IV = seq big-endian + 8 B cero) y anti-replay.
      Espejo de `sealMessage`/`openMessage` de session.ts; **interop byte a
      byte contra WebCrypto** (Node). Demo E2E en vivo: `/v1/echo` (attest →
      session → sellar → descifrar → re-cifrar). 13 tests + 3 interop.
      Nota honesta: v1 usa **AES-GCM** (nativo en WebCrypto), no el
      ChaCha20-Poly1305 del ADR — desviación documentada en session.ts.
- [x] Subdominio por tenant + emisión de cert RA-TLS (interfaz): `gateway/ratls.py`
      — `validate_tenant_domain` (forma estricta del subdominio: sin IP/wildcard/
      userinfo), `DevRATlsProvider` (cert autofirmado ECDSA P-256, SAN=subdominio,
      MARCADO `dev-unattested`, vínculo re-verificable `verify_ratls_binding`),
      `RealRATlsProvider` que FALLA (no degrada). Implementación real (SEV-SNP/TDX)
      pendiente de vendor, aislada aquí. 8/8 tests.
- [x] UI: pintar el estado de atestación de forma permanente (nunca ocultarlo):
      `app.tsx` añade la pastilla de atestación SIEMPRE visible en el header,
      derivada de `attestation_ref` del directorio (`deriveAttestationState`):
      `attested` (ember/ok), `dev-unattested` (ámbar + aviso en tooltip),
      `unknown` (neutro). Ya no se maquilla de "verificado" en dev. i18n ES/EN
      (`attest.*`), CSS `.connection.warn`, 3 tests. `tsc` limpio, 135/135, build OK.
